## 优先补足的证据与边界

1. **恢复云端 CI 执行。** 当前 GitHub 账户计费锁定使任务在步骤开始前失败，不能作为代码测试失败，也不能写成通过。账户所有者处理锁定后重跑，核对前端、Java/MySQL、Compose 三项和 artifacts。配置及本地容器检查均已具备。
2. **本轮已补真实界面证据。** Chromium156，320/375/390px基本页面与375px实际注册/三图批量/登录；Tab/Shift+Tab/Escape/焦点返回；终态停请求、离页/切换、刷新恢复通过。首轮焦点和HTTP随机键失败保留，见ACCOUNTS_QA。剩余是实体手机/iOS/屏幕阅读器与人工审查，不冒称已完成。
3. **演示“异常仍然正确”。** A真实任务查询在浏览器网络层注入500、B正常成功，A保留RUNNING后恢复、终态不再查询，已有JSON/截图。可现场按README重复演示业务阶段失败与用户隔离，讲清查询错误和任务FAILED的差异。

## 可选增强，不作为已完成项

结果 PNG 下载、保留参数重新制作、时间线总耗时汇总可提高操作便利；仅在上述验收完成后按需要做。任务重试要创建新任务并保留旧记录，不能重置原任务终态。当前未新增这些交互。

真实AI、积分、支付、第三方登录、复杂模板后台和消息队列均在原题范围之外。按用户明确要求新增的用户名密码登录是真实持久化功能，仍保留独立Demo入口；不为了展示更多按钮添加假邮箱验证或假找回密码。

## 建议的现场演示顺序

选择 Alice → 个人中心保存昵称/头像 → 刷新确认资料 → 从我的任务批量提交三组素材，其中一组指定生成失败 → 继续浏览并返回任务 → 展示两个同时处理、最终成功/失败各自独立 → 查看结果和真实阶段时间线 → 切换 Bob 查看独立资料与记录 → 退出并重新选择 Alice。

资料多页面冲突另演示：两个页面读取相同版本，先在一个保存，另一个保存应收到 409，保留草稿并要求重新加载；不静默覆盖新资料。已用真实 API 与测试验证此版本条件，真实双标签页操作待人工确认。
