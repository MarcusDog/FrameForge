更新时间：2026-11-04。以下是 AI 根据 EXAM_SPEC.md 的评价重点给出的优先级判断，不是招聘方评分表，也不保证分数。个人中心资料编辑是 R-10 的增强；题目不强制头像或昵称。

## 优先补足的证据与边界

1. **恢复云端 CI 执行。** 当前 GitHub 账户计费锁定使任务在步骤开始前失败，不能作为代码测试失败，也不能写成通过。账户所有者处理锁定后重跑，核对前端、Java/MySQL、Compose 三项和 artifacts。配置及本地容器检查均已具备。
2. **做一次当前版本的真实界面验收。** 桌面及 375px 宽度；Tab 操作上传、资料表单、预览关闭和用户切换；用真实浏览器观察多任务结束后无请求、离开/切换后取消。当前保留旧截图，不把它们冒充新资料页的验收结果。待人工确认。
3. **演示“异常仍然正确”。** 按 README 同时制作成功与指定阶段失败，刷新后恢复，再切到 Bob；展示服务端时间线及 A 查询 500/B 成功的真实测试案例。讲清 HTTP 错误与任务 FAILED 的差异，比堆更多业务更贴合 R-04～R-08。
4. **说明资源边界。** 当前上传替换、未保存头像不会自动回收服务端文件，媒体没有用户配额；真实部署前可补有归属/引用检查的清理和配额。不能直接删旧文件，历史任务及头像可能仍引用它。该扩展尚未实现。

## 可选增强，不作为已完成项

结果 PNG 下载、保留参数重新制作、时间线总耗时汇总可提高操作便利；仅在上述验收完成后按需要做。任务重试要创建新任务并保留旧记录，不能重置原任务终态。当前未新增这些交互。

真实 AI、积分、会员支付、第三方登录、复杂模板后台和消息队列均在原题范围之外。当前 Demo 身份按设计可主动切换，给它增加假密码或假邮箱验证不会增强验收可信度。

## 建议的现场演示顺序

选择 Alice → 个人中心保存昵称/头像 → 刷新确认资料 → 从我的任务批量提交三组素材，其中一组指定生成失败 → 继续浏览并返回任务 → 展示两个同时处理、最终成功/失败各自独立 → 查看结果和真实阶段时间线 → 切换 Bob 查看独立资料与记录 → 退出并重新选择 Alice。

资料多页面冲突另演示：两个页面读取相同版本，先在一个保存，另一个保存应收到 409，保留草稿并要求重新加载；不静默覆盖新资料。已用真实 API 与测试验证此版本条件，真实双标签页操作待人工确认。
